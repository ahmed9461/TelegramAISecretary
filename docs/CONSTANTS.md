# Project Constants — الثوابت المعتمدة

هذا الملف يجمع الثوابت التي لا يجوز تغييرها ضمن تعديل عادي. أي كسر متعمد لأحدها يحتاج قرارًا معماريًا صريحًا في `DECISIONS.md` وتحديثًا للمواصفات.

## المنتج والمنصة

- Telegram Bot API الرسمي هو قناة Telegram المعتمدة؛ لا Userbot ولا جلسة حساب مستخدم غير رسمية.
- الرد نيابة عن المالك يتم عبر Telegram Business / Connected Business Bot و`business_connection_id`.
- لوحة الإدارة Owner-only، والمستخدم غير المصرح له لا يحصل على أدوات الإدارة.
- Telegram مجرد Adapter؛ منطق المعرفة والذاكرة والسياسات والمحادثة لا يعتمد على aiogram.
- البنية يجب أن تسمح بإضافة Adapter آخر مستقبلًا دون إعادة بناء عقل السكرتير.

## المرونة

- النشاط، الخدمات، المنتجات، الأسعار، السياسات، القوائم، الأزرار، النوايا والمسارات هي **بيانات** وليست شروطًا ثابتة في Core.
- يمنع إضافة منطق من نوع `if business == ...` لخدمة أو نشاط بعينه.
- أوضاع الواجهة المعتمدة: `AI_ONLY`, `CUSTOM_MENU`, `HYBRID`.
- الأزرار يمكن أن تكون دائمة أو سياقية، والظهور السياقي يجب أن يكون deterministic وقابلًا للتفسير، لا اختيارًا عشوائيًا من النموذج.

## الذكاء الاصطناعي

- `AIProvider` قابل للاستبدال؛ المزود الحالي للنص/reasoning والرد النهائي هو DeepSeek.
- `VisionProvider` قابل للاستبدال؛ المزود الحالي لتحليل الصور هو Gemini.
- Gemini يعيد أدلة مرئية منظمة ولا يملك قرار الإرسال النهائي.
- سياسة الأمان المحلية أعلى من قرار النموذج وأعلى من إعدادات النشاط.
- المحتوى القادم من المستخدم والصور والملفات يعتبر untrusted data ولا يتحول إلى تعليمات نظام.
- لا يحق للنموذج اختراع أسعار أو توفر أو مواعيد أو موافقة المالك أو التزامات خاصة بالنشاط.

## المعرفة والذاكرة

- `PUBLIC`: يمكن استخدامه كحقيقة قابلة للقول للعميل.
- `INTERNAL`: يوجه السكرتير، ولا يكشف كتعليمات داخلية للعميل.
- `PRIVATE`: Owner-only ولا يدخل سياق LLM.
- ذاكرة كل Contact معزولة عن بقية الأشخاص.
- `private_notes` لا تدخل سياق LLM.
- الذاكرة تساعد على التخصيص لكنها ليست مصدر حقيقة حالي لسعر/توفر/التزام.
- التعلم من تعديل المالك لا يحدث إلا بعد تأكيد صريح، ويحفظ كتوجيه INTERNAL ما لم يقرر المالك خلاف ذلك عبر إدارة المعرفة.
- لا يختار الاسترجاع حقيقة متعارضة بصمت؛ التعارض الفعال يرفع المسار لمراجعة المالك.
- تعديل المعرفة ينشئ نسخة جديدة ويحافظ على النسخة السابقة، والتراجع عن الدفعة لا يحذف التاريخ.
- مصدر approval يحفظ كـsnapshot وقت الإنشاء ولا يعاد تفسيره من قاعدة معرفة تغيرت لاحقًا.
- اقتراح الذاكرة من المحادثة يبقى `PENDING` منفصلًا ولا يعدل ContactMemory قبل اعتماد المالك.
- الذاكرة الآمنة تحمل provenance/confidence ومدة احتفاظ؛ انتهاء retention يمنع إدخالها إلى LLM.
- كلمات المرور ورموز التحقق وبيانات الدفع ومفاتيح الخدمات والبيانات الصحية لا تحفظ في الذاكرة المشتركة.
- تقييم العميل لا يتحول تلقائيًا إلى knowledge أو memory أو policy أو تعديل prompt.

## الإرسال والأمان التشغيلي

- Approval-first هو الافتراضي الآمن أثناء التطوير والاختبار الحي.
- Global mode يعمل كسقف أمان؛ `AUTO` لا يخفف حالة محادثة أكثر تشددًا مثل `HUMAN_TAKEOVER`, `EXCLUDED`, `PAUSED`.
- Draft approval مرتبط بـconversation revision وله TTL.
- رسالة/تعديل/حذف أحدث أو رد يدوي من المالك يبطل المسودة القديمة.
- فحص Telegram `can_reply` يتم مباشرة قبل الإرسال المعتمد.
- الإرسال غير المؤكد للعميل لا يعاد تلقائيًا منعًا للتكرار.
- retry التلقائي على Telegram مسموح فقط لطلبات الإدارة/المالك التي يمكن تحمل تكرار بطاقتها، وليس رد العميل نفسه.

## Rich Messages وUI

- تنسيق ردود العميل يستخدم Telegram native entities؛ لا نعتمد على HTML أو Markdown خام صادر من النموذج.
- الأزرار Inline Keyboard وتمر عبر Telegram adapter.
- رابط الزر يستخدم URL button حقيقي عندما تكون القيمة URL صالحة.
- النص الظاهر للمستخدم أو المالك لا يعرض reason codes أو أسماء providers أو حالات برمجية خام.
- المساعد يقدم نفسه كسكرتير للنشاط، ويتجنب العبارة العامة «كيف أقدر أساعدك اليوم؟».

## البيانات والتشغيل

- PostgreSQL هو مصدر الحقيقة للإنتاج.
- SQLite مسموح كبديل محلي للاختبارات البسيطة فقط.
- Alembic هو مسار schema migrations؛ لا تعدل schema يدويًا في الإنتاج.
- لا تحذف Docker volume أثناء تحديث عادي.
- الأسرار في `.env` أو secret store فقط؛ `.env` وأي backups/keys لا تدخل Git.
- `.env.example` يحتوي placeholders فقط.
- `/health` هو liveness فقط؛ `/ready` هو بوابة الاعتماد على DB/Alembic/الإعدادات ولا يعيد نجاحًا عند عدم الجاهزية.
- metrics التشغيلية aggregate بلا نصوص رسائل، وتكون محمية بـ`METRICS_TOKEN` في الإنتاج.
- AiRun/audit/logs لا تنسخ prompt أو نص المحادثة أو secrets أو private notes.
- السجلات الإنتاجية JSON وتطبق redaction قبل الكتابة؛ trace IDs ليست معرفات مستخدمين.
- النسخة الاحتياطية لا تعتبر صالحة حتى تنجح بروفة استعادة معزولة؛ قاعدة البروفة وحدها تحذف بعد الاختبار.
- تشغيل Docker للتطبيق يكون بمستخدم غير جذر، وربط PostgreSQL وAPI الخارجي يبقى على loopback ما لم يوجد proxy/firewall موثق.
- قيم `change-me` أو metrics token الفارغ غير مقبولة في production preflight.

## الإعدادات الافتراضية الحالية

- Python: 3.12+
- aiogram: 3.x
- Approval TTL: 24 ساعة
- Message debounce: 1.5 ثانية
- Recent context limit: 12 رسالة
- Knowledge top-k: 6
- Memory retention: 365 يومًا
- Memory suggestion TTL: 72 ساعة
- Feedback buttons: مفعلة، وتظهر افتراضيًا كل 3 ردود معتمدة في المحادثة
- PostgreSQL local host port في Docker: 5433 → container 5432
- Metrics window: 30 يومًا
- Backup retention: 30 يومًا
- Structured log format: JSON

هذه القيم الافتراضية قابلة للضبط من الإعدادات، لكن تغيير معناها أو إزالة آلية الحماية المرتبطة بها يحتاج مراجعة قرار معماري.

# M8 — Memory Intelligence & Feedback

## الهدف

تحويل ذاكرة الشخص من حقول يدوية بسيطة إلى ذاكرة قابلة للمراجعة والتدقيق، دون أي تعلم صامت، وإضافة قياس اختياري لرضا العملاء لا يغيّر المعرفة أو الردود تلقائيًا.

## ما نُفذ

- اقتراح ذاكرة من آخر المحادثة عبر DeepSeek، مع اعتبار النص غير موثوق.
- حفظ الاقتراح في `memory_suggestions` بحالة `PENDING` دون لمس `contact_memories`.
- معاينة عربية واعتماد أو رفض صريح من المالك؛ الاقتراح السابق المعلق يصبح `SUPERSEDED`.
- فصل واضح بين الملخص والحقائق والتفضيلات والملاحظة الخاصة.
- `provenance_json` و`confidence_json` لكل قسم، مع مصدر الرسائل ووقت الاعتماد.
- مدة احتفاظ قابلة للضبط؛ الذاكرة المنتهية لا تدخل سياق الصياغة.
- تعديل يدوي للحقائق والتفضيلات بصيغة `العنوان: القيمة`، مع مصدر `OWNER_MANUAL` وثقة كاملة.
- تصدير JSON للمالك فقط، ومسح بتأكيد صريح مع إلغاء الاقتراحات المعلقة.
- تنقية محلية من رموز التحقق والبطاقات وIBAN ومفاتيح الخدمات والبيانات الصحية، حتى لو أعادها مزود AI.
- جدول `feedback` وتقييم 1–5 من العميل الذي استلم الرد فقط، مع إمكانية تحديث تقييم الرد نفسه.
- إظهار طلب التقييم كل عدد قابل للضبط من الردود، وليس بعد كل رد بصورة hardcoded.
- شاشة `📊 رضا العملاء` للمالك تعرض المتوسط والتوزيع. التقييم لا يُحوّل إلى تعلم أو معرفة تلقائيًا.
- migration `0006_m8_memory_intelligence` وأداة بروفة معزولة `scripts/rehearse_migrations.py`.

## الثوابت الأمنية

1. لا توجد كتابة إلى ContactMemory قبل اعتماد المالك.
2. `private_notes` لا تدخل LLM ولا تُرسل للعميل؛ نسخة التصدير التي تحتويها تذهب للمالك فقط.
3. تعطيل `memory_allowed` يمنع اقتراح الذاكرة لذلك الشخص.
4. `share_with_ai=false` والـretention المنتهي يمنعان إدخال الذاكرة الآمنة إلى سياق الرد.
5. الذاكرة ليست مصدر حقيقة لسعر أو توفر أو التزام تجاري.
6. التقييم لا يغير prompt أو policy أو knowledge تلقائيًا.

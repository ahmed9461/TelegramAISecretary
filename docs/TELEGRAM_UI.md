# Telegram UI

## واجهة المالك

لوحة الإدارة Owner-only وتستخدم InlineKeyboard. الأقسام الحالية تشمل المحادثات/الانتظار، عقل السكرتير، تغذية العقل، الأشخاص، الواجهة والأزرار، السلوك، الأوقات، الإحصائيات والأمان بحسب ما هو موصل فعليًا أو ما يزال placeholder. قسم الإحصائيات موصل في M8 لعرض رضا العملاء.

القسم المركزي:

```text
🧠 عقل السكرتير
├── 🏢 الهوية
├── 📚 المعرفة
├── 📥 تغذية العقل
├── 👥 ذاكرة الأشخاص
└── 🎛️ قواعد الرد
```

## Approval Card

بطاقة الرد المقترح للمالك تدعم حاليًا:

- ✅ إرسال الرد
- ✏️ تعديل الرد
- 📚 المصادر
- 🧠 تعلّم من تعديلي
- ❌ رفض

الأزرار مرتبطة بنفس Approval ID. one-shot claim يمنع إرسال نفس approval مرتين.

## Rich Messages للعملاء

الردود المرسلة عبر Telegram Business تمر على native rich renderer. الهدف هو تنسيق Telegram حقيقي عبر `MessageEntity` وليس HTML أو Markdown خام.

الـAI ينتج نصًا نظيفًا. الـrenderer هو المسؤول عن entities حتى لا يتم تفسير syntax غير موثوق من النموذج.

## ذاكرة الأشخاص

شاشة الشخص تعرض الملخص والحقائق والتفضيلات والملاحظة الخاصة وحالة المشاركة وتاريخ المراجعة. تدعم:

- تعديل summary/facts/preferences.
- owner-only private note.
- اقتراح من آخر المحادثة ثم اعتماد/رفض صريح.
- تصدير JSON للمالك فقط.
- مسح مع confirmation دون حذف سجل المحادثة.

لا تعرض الشاشة أكواد حالات داخلية، وتوضح أن الاقتراح لا يحفظ قبل الاعتماد.

## تقييم الرد

عندما يحين التكرار المهيأ، يضاف صف `1⭐ … 5⭐` إلى رد Business مع المحافظة على أزرار القائمة الموجودة. لا يقبل callback إلا من الشخص الذي استلم الرد. شاشة `📊 رضا العملاء` تعرض المتوسط والعدد والتوزيع للمالك.

## واجهة وأزرار العميل

Menu/Button Engine يدعم أوضاع:

- `AI_ONLY`: بدون قائمة مضافة لردود AI.
- `HYBRID`: AI + أزرار مناسبة.
- `CUSTOM_MENU`: واجهة أزرار كخيار رئيسي عندما يكتمل flow المطلوب.

أنواع الأفعال الموصلة حاليًا:

- `SEND_MESSAGE`: يرسل نصًا ثابتًا.
- `OPEN_URL`: زر URL حقيقي.
- `HANDOFF`: يحول المحادثة إلى `HUMAN_TAKEOVER` ويبلغ المالك.

## ظهور الأزرار

### 🌐 دائم
`visibility_rules_json.mode = ALWAYS` أو قواعد فارغة قديمة. يظهر مع الرد عندما يسمح وضع الواجهة.

### 🎯 سياقي
`mode = CONTEXTUAL` مع keywords و/أو intents. يظهر فقط عند تطابق سياق الرد، مثل:

```text
زر: ⭐ الدفع بالنجوم
keywords: دفع، سداد، نجوم، تحويل
```

إذا كان سؤال العميل عن الدفع أو رد السكرتير يتضمن سياق الدفع يظهر الزر. سؤال غير متعلق بالدفع لا يظهر معه الزر.

الفلترة deterministic وليست اختيارًا عشوائيًا من LLM.

## قواعد تصميم UI

- لا تضع كل الأزرار تحت كل رد.
- اجعل الزر contextual افتراضيًا عندما يخدم موضوعًا محددًا.
- استخدم ALWAYS فقط للأفعال العامة فعلًا مثل تواصل بشري دائم إذا أراد المالك ذلك.
- لا تعرض زرًا لا يملك action صالحًا.
- callback يجب acknowledgment مبكرًا؛ استخدم safe callback handling.
- عند تعديل شاشة إدارة يفضل edit لنفس الرسالة عندما يكون ذلك واضحًا، وإرسال رسالة جديدة فقط عندما يحتاج FSM إدخالًا من المالك.

## Business Callback Requirements

الزر المرسل عبر Business Connection يجب أن يبقى مرتبطًا برسالة تحتوي `business_connection_id`. handler يستخرج chat + connection من callback message ثم ينفذ action عبر Telegram Adapter.

## روابط

OPEN_URL لا يستخدم callback_data؛ عند وجود `http://` أو `https://` صالح يحول إلى InlineKeyboardButton(url=...). القيم غير الصالحة لا يجب أن تصبح زر رابط.
